## 核心项目逐字稿 · 代码图谱引擎 + MCP（90 秒版）

> 这个项目的背景：Agent 要回答代码问题，但传统检索只给文本片段，给不了函数调用链、依赖关系这种结构化事实。所以我在华为推动做了两件事：
>
> 一是多语言代码图谱。第一版 Python 用三套解析器：Clang AST 管 C/C++、Jedi 管 Python、LSP 管 Java。后来用 Go 重写，树解析用 tree-sitter，工程语义靠 LSP 补齐。四语言输出语义和 Python 基线逐字段对齐，我用一个验收 harness 跑 73 个用例验证，73/73 全过。这里有个关键设计叫 LangSpec——语言无关的遍历器配一份语言特化规格，保证不同语言的解析结果语义一致；Graph Buffer 负责跨文件合并，节点确定性去重，输出可复现。
>
> 二是 MCP 服务。我给大模型暴露了 9 个工具：search_code、get_file_dependencies、search_error_log 这类，输入输出 Schema 化，返回的是代码事实而不是模型的猜测。这样 Agent 可以按图索骥。
>
> 结果上，这个项目本身是 Agent 驱动交付的：1 个月 134 个 commit、132 个 issue 闭环，5 个仓库 CI/CD 一次性打通，coverage 不低于 82%。
>
> 最难的地方是语义对齐——四语言各走各的 AST，怎么保证一个函数调用从不同语言解析出来的链是一样的。我的解法是 LangSpec 规格化 + 验收集逐字段对比，靠用例逼出差异。如果重新做，我会在解析层次上更早引入 LSP 的符号表，减少后面补语义的返工。

**逐字稿练习要点**: 讲 3 遍 > 背 10 遍; 每段控制在 15-20 秒; 数字停顿

## FaultPro 逐字稿（45 秒版）

> 第二个项目是设备故障诊断。RAG 知识库清洗到精排全链路，加一个 eBPF 慢 IO 定界工具，在 VFS、IO 调度器、NFS 节点分段测时延，采集开销不到 2%。最后用 opencode 搭了批量诊断工作流，超时续跑、部分输出复用，把日志诊断、故障链建立、知识库沉淀串成闭环。
