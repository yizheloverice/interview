## 1. MCP 协议深挖（你已实践, 补术语）

**定义**: Model Context Protocol, Anthropic 2024-11 开源。给 LLM 应用提供标准化的工具/资源/提示词接口。角色: Host(如 Claude Code)/Client(与 server 通信)/Server(暴露能力)。

**关键点**:
- 原语: **Tools**(函数调用, 有 schema)、**Resources**(数据源)、**Prompts**(模板)
- 传输: stdio(本地) / Streamable HTTP(远程); 新协议升级: 逐步废弃 SSE 持久连接
- 工具发现: client 动态读 server 的 tools/list, 不需要预先硬编码
- 工具描述 token 优化: 描述越长占用上下文越多 → 精炼描述是工程调优点

**面试口径**: "MCP 的价值是协议标准化——我做的代码图谱服务不需要为每个 Agent 客户端写适配, 一次实现 9 个工具, 任意支持 MCP 的 Agent 都能发现和调用。工具 schema 化, 返回的是代码事实而非文本猜测。工程上我控制每个工具描述的长度, 因为描述也进上下文, 会挤占 token 预算。"

**自测题**: ①MCP 和普通 REST API 的差别? ②streamable HTTP 相对 SSE 改进了什么? ③一个 Agent 如何发现你的工具?

## 2. Agent 编排框架（概念级）

**定义**: LangGraph(图状态机, 节点/边/State/检查点, 可长期运行状态); CrewAI(角色制多智能体: Agent/Task/Tool); AutoGen(会话式多代理); Dify(低代码, 面向业务)。

**面试口径**: "我主要自建工具链(MCP+代码图谱), 没有重度依赖编排框架; 对编排的理解是: 框架解决『状态管理与流程复用』, LangGraph 的图模型与我的验收工作流对应——我的 SDD 流程其实就是一个 DAG: 需求 → 规格文档 → 实现 → harness 验证 → 门禁放行, 每步可检查点、可回溯。选型上我倾向小而专的工具, 而不是大而全的框架, 因为 Agent 能力的上限在模型和工具质量, 不在框架。"

**自测题**: ①LangGraph 的 checkpoint 解决什么问题? ②为什么说框架不决定 Agent 上限?

## 3. A2A 协议（面鼎桥必考）

**定义**: Agent2Agent, Google 2025-04 发布(与 MCP 互补)。MCP 管 Agent↔工具, A2A 管 Agent↔Agent。核心概念: Agent Card(能力声明, 类似 JSON 清单)、任务生命周期(提交/执行/完成/取消)、已证明消息模式(带证据的响应)。

**面试口径**: "A2A 是 Agent 之间的协作协议, MCP 是 Agent 与工具之间的。类比: MCP 给 Agent 加了手脚, A2A 让多个 Agent 组织成团队。我的项目是 MCP 侧; 多 Agent 协作层面, 我在批量诊断工作流里做过超时续跑与部分输出复用——这本质是任务状态机+消息传递, 与 A2A 的任务生命周期相通。"

**自测题**: ①MCP 与 A2A 的区别? ②Agent Card 的用途?

## 4. 混合检索 + Rerank（面 RAG 岗必考）

**定义**: 语义检索(dense embedding, 相似度) 的短板是精确词/专有名词; 稀疏检索(BM25/倒排, 词法) 精通精确匹配但不懂语义 → **混合检索**: 两路召回 → 融合(RRF 倒数排名融合/加权) → 可加 Rerank(精排模型 2-4 分延迟换准确率)。

**面试口径**: "我在 FaultPro 里做的是清洗→向量检索→精排链路。工程体验上: 故障日志含大量精确 token(函数名、错误码), 纯向量检索会召回近义但错误的日志, 混合检索(词法+语义)是标准解法; rerank 用更重模型对 top-50 精排到 top-5, 代价是几十毫秒。召回率评测我用标注样本算召回率/NDCG, 我的验收 harness 73/73 就是这类评测的工程化。"

**自测题**: ①RRF 怎么融合? ②rerank 放在哪个阶段, 成本怎么控制? ③chunk 切分策略影响什么?

## 5. Agent 沙箱 + Human on the Loop（面鼎桥/蚂蚁必考）

**定义**: 沙箱=受限执行环境(隔离/资源限制/网络白名单): Docker 容器(cgroup/namespace 隔离)、gVisor(用户态内核)、nsjail、远程 VM(如 DSec)。Human on the Loop=关键节点人工介入: 审批步/审计日志/超时确认/权限分级。

**面试口径**: "沙箱我直接的经验是 Docker 隔离与 CI/CD 双平台门禁——agentic coding 场景下 pre-push 门禁 + 人工 code review 就是 Human on the Loop 的一种: 机器产出, 人在提交点干预。更深的隔离(gVisor/namespace)我正在补。可观测性是我强项: eBPF 追踪可以在沙箱里按 IO/网络分段定位 Agent 行为, 采集开销 <2%。"

**自测题**: ①cgroup 和 namespace 各管什么? ②Human on the Loop 在工程流程里怎么落地(给出一套设计)?

## 6. vLLM / TensorRT-LLM（概念级）

**定义**: vLLM=gpt 高效推理引擎, 关键 **PagedAttention**(把 KV cache 分页管理减少碎片/不足导致的空间浪费, throughput 提升数倍) + 连续批处理(continuous batching)。TensorRT-LLM=NVIDIA 编译优化框架, 针对特定 GPU 做算子融合/量化。

**面试口径**: "我对推理引擎的理解在概念层+模型经验: 做过 DPO 微调(训练侧), GPU 训练环境搭建过。推理侧我清楚 vLLM 的价值: KV cache 管理是吞吐瓶颈, PagedAttention 解决碎片化; 私有化部署场景调度/量化是工程重点。如果入职做这块, 我可以快速补齐。"

**自测题**: ①PagedAttention 解决的痛点? ②continuous batching 为什么提升吞吐?

## 8. Tracing / 可观测性（面腾讯混元必考）

**定义**: OpenTelemetry: trace(一次请求完整链路)/span(单个操作: 名称/时延/属性)/attribute(键值); 采样与低开销采集是工程关键。Agent traversing: 一次 Agent 任务从 Prompt→工具调用→生成→反馈全链 span 记录, 用于调试+评测。

**面试口径**: "eBPF 让我建立了观测心智: 关键路径挂点、开销预算(<2%)、分段聚合、定位瓶颈。混元岗的 Agent tracing & observability 我理解是: 把 Agent 每步动作(检索/工具调用/生成)变成 span, 串成 trace; 评估体系(A/B/regression)依赖 trace 数据沉淀。我的验收 harness + coverage 门禁就是'评估闭环'的工程版。"

## 9. Agent 记忆系统（Memory）★ 新增(字节 A156991/A26329 考点)

**定义**: 短期(对话上下文) + 长期(跨会话) + 任务记忆。实现要点: 记忆的表征(原始文本/结构化/向量)、存储与索引(向量库/键值)、检索(语义+时间衰减+相关性)、更新(合并/冲突消解)、压缩(摘要/遗忘策略)、生命周期(写入-更新-过期)。

**与 RAG 的区别**(面试高频): RAG 查询外部知识库; Memory 是 Agent 自身经历的沉淀。都是检索, 但记忆关注"这次会话学到什么"与个性化, 知识库关注"领域事实"。

**面试口径**: "我理解记忆系统的核心难点不是存储, 而是遗忘与冲突消解——记忆膨胀会挤占上下文, 需要分层(热记忆/冷记忆)与摘要压缩; 我项目里的 Graph Buffer 做过确定性去重与合并, 这是记忆合并的基础心智; 检索替代长上下文(context engineering)是当前主流方向。"

**自测题**: ①Memory 与 RAG 区别? ②记忆膨胀的工程解法?

## 10. 数据飞轮 + Evaluation Harness 术语化 ★ 新增(字节/鼎桥/阿丽云 JD 高频)

**定义**: 数据飞轮 = 用户反馈→数据沉淀→评测→模型/Agent 迭代→更好体验→更多反馈 的闭环。Evaluation Harness = Agent 评估框架: 基准任务集 + 运行器(跑 Agent) + 指标(任务完成率/准确率/鲁棒性/延迟/成本) + 结果对比与回归检测。

**面试口径(你的 73/73 harness 就是 Harness)**:
"我在代码图谱引擎上建过验收 harness: 73 个对齐用例按语言×查询类型组织, 每次 Agent 改动后跑全量, 73/73 与 coverage 82% 作为 pre-push 门禁——这就是 Evaluation Harness 的完整形态: 给定任务集、自动执行、量化指标、回归兜底。数据飞轮上, 我的 CMC 数据管道(ETL 增量/异步化)就是反馈数据沉淀的底座。"

**自测题**: ①Harness 需要哪些组件? ②数据飞轮的驱动指标怎么定?

## 11. SDD（Spec 驱动开发）+ 知识工程 + 任务规划（三合一, 分散在多家 JD）

**定义**:
- SDD: 先写规格(Spec)→ 模型实现 → 规格验证; 你的 pre-push 门禁+验收 harness 就是实践
- 知识工程: 把领域知识结构化(实体/关系/规则)喂给 Agent, 与 RAG 的差异在于"结构化知识库 vs 非结构化文档检索"; 你项目里 LangSpec(语言特化规格)就是知识工程的一种
- 任务规划(Planning): ReAct/Plan-and-Execute/反思; 任务分解→子任务执行→验证→重规划; 你的 opencode 工作流(超时续跑/结果复用)就是规划-执行-重试的结构

**面试口径**: "SDD 我直接实践过: 先把每语言的对齐用例写成规格, 再让 Agent 按规格实现, 验证通过才算完成——所以我的 134 commits 里即使有失败尝试, 也不会污染主线。知识工程与规划, LangSpec 规格与批量诊断工作流是两个对应物。"

**自测题**: ①SDD 与传统 TDD 区别? ②规划器怎么处理子任务失败?

## 12. 私有化部署 + FDE 交付能力（DeepSeek/FDE 岗补充, 概念+软技能）

**定义**: 私有化部署 = 模型服务装入客户环境(Docker/K8s/GPU 调度/安全合规/监控), 关注: 镜像构建、显卡驱动与 CUDA、模型网关(统一入口/限流/熔断)、推理引擎(vLLM 主题 6)。FDE 能力 = 客户访谈→需求抽象→方案设计→PoC→验收指标设计→上线交接; 关键: 把业务诉求翻译为可测量指标。

**面试口径**: "我做过 5 仓 CI/CD 双平台打包(PyInstaller 跨平台), 对构建、门禁、发布链路熟; 私有化部署我理解重点是推理引擎选型+显卡资源规划+监控告警。FDE 侧, 我的故障诊断项目就是按'业务目标→验收指标→交付闭环'交付的, 诊断成功率与根因命中率是验收指标。"

**自测题**: ①模型网关做什么? ②验收指标设计的两个要素(可测量/可归因)?
