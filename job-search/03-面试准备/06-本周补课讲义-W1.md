## 第 1 课 · MCP 协议深挖（你已实践, 重点补术语与边界）

### 1.1 一句话定位
MCP(Anthropic, 2024-11)= **模型与工具之间的标准化接口**。你做过 MCP 服务——想想为什么做: 为了让 Claude/Codex/opencode 都能发现代码图谱工具, 而不是为每个 Agent 写适配器。**一次实现, 处处可发现**, 这就是协议的价值。

### 1.2 核心概念(背三个角色+三个原语)
- Host: 发起会话的 Agent 应用(Claude Code/Cursor)
- Client: Host 与 Server 之间的协议连接组件(一个 Host 可多个 Client)
- Server: 暴露能力的进程(你的代码图谱 MCP 服务)

原语:
- **Tools**: 可调用函数, 带 JSON Schema(你的 search_code/get_file_dependencies)
- **Resources**: 只读数据源(文件/数据库/文档)
- **Prompts**: 可复用提示模板

### 1.3 传输与协议演进
- **stdio**: 本地进程管道(部署简单, 无网络面)
- **Streamable HTTP**: 远程服务(2025 年后主流); 旧版是 HTTP+SSE, 新协议改为**流式响应单传输 + 会话可恢复**(简化部署, 支持流式工具响应与断开重连)
- **工具发现**: client 调 tools/list, 动态拿到清单 → 新增工具无需改客户端代码
- **描述 token 优化**: 工具 name/description 会进上下文预算, 描述越精炼越省 token; 这是真实工程调优点

### 1.4 对比题: MCP vs Function Calling vs REST API
| 维度 | Function Calling | MCP | REST API |
|---|---|---|---|
| 定位 | 模型单次调用规范 | 工具层协议(发现+调用+标准化) | 具体接口实现 |
| 动态发现 | 需每次提示里写 | tools/list 自动发现 | 客户端硬编码 |
| 跨生态 | 绑定 provider(OpenAI/Anthropic 各自) | 跨厂商标准 | 无 |
| 工具描述管理 | 每次拼 prompt | 服务端统一管理 | 无 |

**答题模板**: "Function Calling 是模型侧一次调用的格式规范; MCP 是工具侧的服务化协议——把工具如何被发现、什么 Schema、什么边界都标准化。我的服务一次实现, Claude/Codex 都能直接发现 9 个工具调用, 这就是协议层的价值。"

### 1.5 面试硬问题 Q&A(30 秒版)
- **Q 安全边界?**: A "工具级权限(只读/写分级), server 侧校验输入, 敏感元数据不暴露; 我内网场景是可信环境+最小工具暴露"
- **Q 为什么不用普通 API?**: A "普通 API 要每个客户端写调用逻辑; MCP 解决发现/描述/复用三件事, 多 Agent 场景改一处全生效"
- **Q 你的 9 个工具怎么抽的?**: A "按代码事实类型切: 搜索类→依赖类→错误定位类→外部调用类, 每类 Schema 化输出"（注意: 说"按事实类型切分"这个抽象, 不要报流水账）
- **Q 工具调用失败怎么处理?**: A "错误码+重试语义进工具返回, 让模型自己判断降级; 我的 search_error_log 就是错误定位类, 返回结构化故障信息"（结合项目）

## 第 2 课 · A2A 协议（面鼎桥必考）

### 2.1 定位(最常考提问)
- **MCP: Agent ↔ 工具**(给 Agent 加手脚)
- **A2A: Agent ↔ Agent**(让 Agent 组队)
互补不竞争。只懂 MCP = 单人车间; 加 A2A = 生产线。

### 2.2 两个核心概念
- **Agent Card**: Agent 能力声明(JSON: 能做什么/协议版本/输入输出)——类比: 你的简历, 协作方(其他 Agent)通过它决定要不要派活
- **任务状态机**: submit → working → completed/handoff; **已证明消息**(带证据的回复: 证据/引用/置信度)

### 2.3 你的项目映射(迁移口径)
"我的批量诊断工作流(opencode: 超时续跑/部分输出复用)本质就是任务生命周期的工程版: 子任务有状态(running/done/failed)、结果可复用(幂等缓存)、失败可重试。A2A 把这种模式标准化了——我从实践中理解它。"

### 2.4 面试三问
- **Q MCP/A2A 关系?**: "MCP 是 Agent-工具, A2A 是 Agent-Agent; 我做过 MCP 侧, 多 Agent 协作上我用任务状态机+消息传递+幂等重试, 与 A2A 的任务生命周期相通"
- **Q Agent Card 用途?**: "能力声明, 协作前让对手方知道我能提供什么、协议是什么, 避免盲导"
- **Q 跨 Agent 失败怎么办?**: "状态机+幂等+重试; 我的超时续跑就是这思路——失败保留状态, 重试不重复劳动"

### 2.5 当课自测

## 第 3 课 · 混合检索 + Rerank（面 RAG 岗必考）

### 3.1 痛点
纯语义检索(dense embedding 相似度)的短板: **精确词/专有名词/错误码**匹配差(比如函数名 `RPC_ERR_1024`, 语义近邻检索不出精确 token); 纯词法(BM25/倒排)懂精确匹配但不懂语义。二者互补。

### 3.2 链路
```
查询 → 双路召回(dense 语义 + sparse BM25) → 融合(RRF 倒数排名/加权) → Rerank(精排模型, 对 top-50 重排到 top-5) → 返回
```
- **RRF**: score = Σ 1/(k + rank_i), 两路各自排名融合, 无需调权——简单稳定
- **Rerank**: 交叉编码器级精排(如 bge-reranker), 2-4 分延迟换命中率; 位置在召回后、输出前: top-50 → top-5
- **chunk 切分**: 按语义段/固定窗口+overlap; chunk 大小影响检索粒度(日志行级 vs 文档级)

### 3.3 你的项目映射
FaultPro: "清洗→向量检索→精排。工程体验上: 故障日志含大量精确 token(函数名/错误码), 纯向量会召回近义但错误的日志, 混合检索是标准解法; rerank 对 top-50 精排到 top-5, 代价几十毫秒。召回率评测: 用标注样本算召回率/NDCG——验收 harness 73/73 就是这类评测的工程化。"

### 3.4 面试 Q&A
- **Q 混合检索为什么不用一个模型搞定?**: "语义与词法互补, 单模型在精确 token 场景掉点; 工程上双路+融合成本可控"
- **Q RRF 凭什么不调权?**: "两路都是 top-k 召回, 排名信息比绝对分数更稳, RRF 用排名避免分数尺度不可比"
- **Q rerank 成本?**: "精排只跑 top-50, 单文档几十 ms; 延迟预算紧可以只用召回+阈值, 或对查询分类决定要不要 rerank"
- **Q 怎么评估检索质量?**: "标注集+召回率/NDCG; 每类查询单独统计(专有名词类/描述类/长尾类)"

### 3.5 当课自测

Q6: rerank 放在哪一步? 成本的权衡逻辑是什么?

## 第 4 课 · SDD + 知识工程 + 任务规划（三合一, 多家 JD 出现）

### 4.1 SDD（Spec 驱动开发）
- 定义: 先写规格(Spec)→ 模型按规格实现 → 自动化验证(规格即验收)
- 与 TDD 区别: TDD 是"实现前写测试"; SDD 是"把验收标准写成规格文档, 实现以规格为真值"——对 Agent 开发而言 SDD 是唯一可靠的交付路径(因为模型每次输出不确定)
- **你的实践(直接说)**: "我的验收 harness 73 个对齐用例(按语言×查询类型组织)就是规格; Agent 实现完跑全量, 73/73 与 coverage 82% 是 pre-push 门禁——允许失败尝试, 但只有通过规格的才进主线。这就是 SDD 完整实践。"

### 4.2 知识工程（结构化知识喂给 Agent）
- 定义: 把领域知识组织为**结构化知识库**(实体/关系/规则/schema), 与 RAG(非结构化文档检索)互补
- **你的实践**: "LangSpec 框架(语言无关遍历器+语言特化规格)就是知识工程的一种——把 C/C++/Java/Python 的语义规则结构化, Agent 通过 MCP 拿到的都是规格化的代码事实, 而不是自由文本"

### 4.3 任务规划（Planning）
- 三种模式:
  - **ReAct**: 推理-行动循环(think→act→observe)
  - **Plan-and-Execute**: 先分解计划再执行(子任务列表)
  - **反思/自我修正**: 每步完成后验证并修正
- **你的实践**: "opencode 批量诊断工作流就是 Plan-and-Execute + 反思: 任务分解→子任务(超时续跑=状态保活, 结果复用=幂等缓存), 完成了才进入知识库沉淀"

### 4.4 面试 Q&A
- **Q SDD 与传统开发差异?**: "传统: 实现-测试-验收; SDD: 验收标准前置, 模型按规格执行, 验证通过才算完成——对 agentic 开发是必要而非可选"
- **Q 规划器子任务失败?**: "状态机+重试+替代路径; 我从超时续跑里积累了'失败保留状态'的实践"
- **Q 知识工程 vs RAG?**: "RAG 查文档, 知识工程是结构化事实; 我两条都做过(RAG: FaultPro; 结构化: LangSpec)"
